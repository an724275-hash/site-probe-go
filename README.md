# Site Probe

CLI для диагностики сайтов на Go. Дополняет Site Watch: позволяет проверить HTTP-ответ, редиректы, DNS, TCP, TLS и срок действия сертификата без запуска Python-сервера.

Используется только стандартная библиотека Go. Сторонние пакеты не нужны.

## Запуск

Нужен Go 1.23 или новее.

```sh
go run ./cmd/siteprobe https://giveaway-one.ru https://sandiegoleatherrepair.com
go run ./cmd/siteprobe -targets targets.example.json -format json
go build -o bin/siteprobe ./cmd/siteprobe
```

В Windows при сборке можно указать `-o bin/siteprobe.exe`.

Пример файла целей:

```json
[
  {"id": "portfolio", "name": "Портфолио", "url": "https://giveaway-one.ru/"}
]
```

Формат совместим с простым списком целей Site Watch. За один запуск можно проверить до 100 адресов; результаты сохраняют порядок входного списка.

## Что проверяется

- HTTP-код и конечный адрес после редиректов.
- DNS, TCP, TLS и время до первого байта ответа.
- IP сервера, версия HTTP и срок действия TLS-сертификата.
- Цепочка редиректов, таймауты, ошибки сертификата и сетевые ошибки.

`ok` означает HTTP 2xx. `restricted` означает 401, 403 или 429: сайт ответил, но ограничил запрос. Это не доказательство, что сайт не работает. Остальные HTTP-коды дают `http_error`, ошибки подключения — `network_error` с отдельным `error_kind`.

## Параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `-targets` | нет | JSON-файл вместо адресов в аргументах |
| `-format` | `table` | `table` или `json` |
| `-timeout` | `10s` | Таймаут одной цели, включая редиректы |
| `-workers` | `4` | Одновременные проверки, от 1 до 32 |
| `-redirects` | `5` | Максимум переходов, от 0 до 10 |
| `-allow-http` | выключен | Разрешить исходные HTTP-адреса |
| `-allow-private` | выключен | Разрешить локальные и зарезервированные IP |

Переход с HTTPS на HTTP запрещён даже с `-allow-http`. TLS-сертификаты проверяются обычным способом; режима отключения проверки нет. DNS-адреса проверяются перед подключением, затем соединение открывается с выбранным IP без повторного разрешения имени. Локальные адреса по умолчанию заблокированы. Это ограничение для диагностики, не полноценный сетевой sandbox.

Для локального сервера:

```sh
go run ./cmd/siteprobe -allow-http -allow-private http://127.0.0.1:8000
```

Код завершения: `0` — все результаты `ok`, `1` — есть другой статус, `2` — неверные аргументы, конфигурация или ошибка записи отчёта. Ctrl+C отменяет текущие проверки. JSON идёт в stdout, сообщения об ошибках запуска — в stderr.

## Ограничения

Это разовая сетевая диагностика, а не мониторинг uptime или браузерный тест. JavaScript не выполняется, весь документ и его ресурсы не скачиваются. Время `total_ms` считается до закрытия тела ответа, `ttfb_ms` — от начала проверки до первого байта последнего полученного ответа. При редиректах DNS/TCP/TLS показывают последнее измеренное соединение, а не сумму всех переходов. DNS для IP-адреса включает только работу resolver, не обязательно сетевой запрос.

Проверки выполняются напрямую: переменные HTTP_PROXY/HTTPS_PROXY не используются. Query-параметры, фрагменты и данные авторизации удаляются из полей URL в отчёте. Имена целей и пути не очищаются от чувствительных данных, поэтому не помещайте в них секреты. Пример содержит публичные сайты; его результат зависит от сети и состояния сайтов в момент запуска.

## Проверки кода

```sh
go vet ./...
go test ./...
```

Тесты используют локальные HTTP/TLS-серверы и не зависят от доступности внешних сайтов. CI запускает их на Linux и Windows.
